# ステルス・ウィザード

> これは遊びです。
> これは運営者の学術的な活動とは別の、エンターテインメントの枠です。科学ではありません。
> 「三十歳まで童貞なら魔法使いになる」という都市伝説を題材にした、娯楽のためのサイトです。
> ここに書く「法則」は、科学の法則ではありません。医学や心理学の主張でもなく、誰の性経験も評価しません。
> 特定の人を魔法使いと呼ぶものでもありません。

サイト：<https://quiet-wizard.vercel.app/>

原理（定義・要請・法則・定理と証明の全文）は、[PRINCIPIA.md](PRINCIPIA.md) で読めます。

元になったのは、運営者が直観から書いた一枚の文「三十歳魔法使い都市伝説について」です。
その文は「本稿は論文とは別のものであり、著者の主体的な直観によるものである」と始まります。
このサイトは、その文から借りた魔法使いの像を、ゲームのクラス「ステルス・ウィザード」に見立てて、遊びとして掘り下げたものです。
ここで言うクラスは、ゲームの職業のたとえです。人を分ける区分ではなく、誰かを当てはめるものでもありません。
2026-11-21 までの名は「地味な魔法使い」です。リポジトリと所在の名（quiet-wizard）は変えていません。

## 参加

参加は、みんなの図鑑に場面を寄せることだけです。
寄せる人が、自分を遊びの参加者や魔法使いとして名を連ねる仕組みは、作っていません。
名を連ねる一覧は、実在の GitHub の利用者を、魔法使いとして並べることになります。
それは、特定の人を魔法使いと呼ばないこと、誰の性経験も評価しないことという決めに触れます。
この形は、2026-11-23 に運営者が GitHub のアカウントを通した参加を求め、Claude が決めました。

- 寄せる様式は、GitHub の issue の様式（`.github/ISSUE_TEMPLATE/entry.yml`）です。法則、題、場面、言葉の欄と、必須の確かめの印と、言語モデルに渡ることへの任意の同意を持ちます。名の表示の欄はありません。様式は `intake/entry.js` から `node build.js` が作る生成物です。
- issue は、開いたその時から GitHub で公開されます。運営者が読む前から、誰でも読めます。
- ワークフロー「みんなの図鑑の受付」（`.github/workflows/entry.yml`）は、ラベル entry の付いた issue の欄と印と寄せの数を `intake/entry.js` で確かめ、ラベルと決まった文のコメントを一つ付けます。issue を閉じず、鍵を掛けず、消さず、何も載せません。issue の題と本文を、式にも環境の変数にもシェルにも渡しません。
- 頁に載せる場面には、寄せた人の名を出しません。`data/entries.json` にも名の欄はありません。issue そのものは、GitHub の決まりで、開いた人の名とともに公開されます。
- 寄せは、一つの GitHub のアカウントにつき、生涯で 3 件までです。受付が、同じアカウントが前に開いたラベル entry の issue を、開いているか閉じたかを問わずに数えます。
- 一つの法則に場面が 5 件載ったら、その法則の寄せは受けません。受付が `data/entries.json` で数えます。図鑑の全体は、多くて 50 件です。様式の法則の選択肢は十のまま置き、5 件載った法則を欄の説明と頁に挙げます。様式は選択肢の無い欄を受けず、受付は選択肢の文で法則を読むためです。
- 上の三つは、2026-11-23 に運営者が決めました。利用規約の決まり（読む人に不利になる変更は、効力の生じる日より前に示す）に従い、2026-11-24 に示して、2026-12-08 から効きます。日数の定めは無く、Claude が二週間と決めました。寄せている途中の人が新しい決まりを読めるようにするためです。
- 載せる場面は、運営者か、運営者の求めで Claude が、PR で `data/entries.json` に足します。頁（`site/entries.html` と英語の頁）は、そこから作ります。Claude は、寄せられた場面を書きません。
- 決まりは、利用規約の「寄せた場面」、個人情報の取り扱いの「みんなの図鑑に寄せた場面」と「言語モデルに渡すこと」、求めと連絡の「みんなの図鑑の場面」、適法性の説明の「参加（みんなの図鑑）の法的な扱い」にあります。
- `node intake/entry.js --self-test` は、作り物の本文と作り物の API で、落ちるべきものを落とすことと、issue を閉じず鍵を掛けないことを確かめます。本物の issue では試していません。

## 作り方

```
node build.js
node verification/check.js
node tools/card.js --check
node verification/check_browser.js
node verification/check_browser.js --break
node intake/entry.js --self-test
node verification/indexnow.js --dry-run
node verification/wayback.js --dry-run
```

`site/` は生成物です。
英語の頁（`site/<名>.en.html`）も、`src/<名>.en.md` から作る生成物です。上の帯と下の欄の英語の断りは `build.js` の `FRAME_EN` と `FOOT_EN` にあり、検査が日本語の断りと同じく固めています。
共有のカードとホーム画面のアイコン（`assets/card.png`、`assets/apple-touch-icon.png`）は、`tools/card.js` が紋と色と書体から描いた PNG です。描き直すときは `node tools/card.js` を使います。Playwright の Chromium が要ります。`src/` と `assets/` を直して作り直します。
`verification/check_browser.js` は、ブラウザでの検査です。`site/` を手元の小さなサーバーで配り、配信の見出しは `site/vercel.json` と同じにします。Playwright の Chromium で、二つの言葉のすべての頁を開きます。
確かめるのは、コンソールの誤りと CSP の違反、携帯と机の幅で明るい配色と暗い配色のどれでも横にはみ出さないこと、キーボードでの移り方とフォーカスの輪、拡大したときの文字、動きを減らす設定、遊び場の動きと読み上げ、言葉の切り替え、ディレクトリの中の存在しない所在で出る 404 の頁、頁の中のつなぎと飛び先です。
確かめの数は、走らせたときに出ます。`--break` は `site/` の写しを壊し、壊し方のどれでも落ちることを確かめます。
CI は、push と PR のたびに、この二つを走らせます。
頁は、ほかのサーバーへ何も要求しません。cookie も、アクセスの解析もありません。
頁そのものは、入力を受け取りません。参加は、GitHub の issue の様式で行います（上の「参加」）。
配信は Vercel で、`site/` を根にしています。
`verification/live.js` は、本番の日本語と英語のはじめにの頁と共有のカードを、ログインなしで外から取り寄せて確かめます。一般の取り寄せ役の名と、X の取り寄せ役の名（Twitterbot）の二つで取り寄せます。ワークフロー「本番」が毎日一度回します。`--self-test` は、作り物の答えで、落ちるべきものを落とすかを見ます。
`verification/indexnow.js` は、`site/sitemap.xml` で lastmod の変わった頁と、増えた頁と消えた頁を、IndexNow（Bing などの検索の仕組みが受ける知らせ）に送ります。
ワークフロー「IndexNow」が、main への push で `site/sitemap.xml` が変わったときに回します。手で起こして all を yes にすると、sitemap の頁を全部送ります。
sitemap の lastmod は、頁の中身（`site/` の HTML）が最後に変わった日です。`node build.js` が、`data/lastmod.json` の控えから書きます。
控えは、頁ごとに、日と中身の SHA-256 を持ちます。作った頁の SHA-256 が控えと同じなら、日はそのままです。違う頁だけを、作った日（日本時間）にします。
同じ中身から作り直しても、日は変わりません。git の履歴を読まないので、浅い複製でも同じ結果になります。
lastmod は日までなので、同じ日に二度変えた頁は、二度目には送りません。
本番の sitemap がそのコミットのものと同じになり、鍵のファイルが読めるようになるまで待ってから送ります。
鍵は `build.js` の `INDEXNOW_KEY` で、`node build.js` が `site/<鍵>.txt` に、中身も鍵そのものとして書きます。鍵は秘密ではありません。
送るのはこのサイトの頁の所在だけで、読む人についての何も送りません。`--dry-run` は、送らずに、送る頁を出します。
Google は IndexNow を読みません。sitemap を読みます（robots.txt が名指しています）。
`verification/wayback.js` は、このサイトの頁の写しを、Internet Archive の Wayback Machine に頼みます（Save Page Now）。
ワークフロー「Wayback Machine」を手で起こしたときだけ回ります。頼むのは `site/sitemap.xml` の頁です。
頼んだあと、頼んだ日の写しがあるかを `archive.org/wayback/available` で確かめます。確かめられたものだけを、残ったものとして要約に出します。一つでも見えなければ、実行を落とします。
みんなの図鑑の頁（日本語と英語）は頼みません。ほかの人が寄せた場面を載せ、求めがあればすぐ外すと決めた頁です。Wayback Machine の写しは、運営者には消せません。
この頁は、`site/robots.txt` で Internet Archive の取り寄せ役（ia_archiver と archive.org_bot）に閉じています。閉じる頁は `build.js` の `ARCHIVE_CLOSED` が決め、`verification/wayback.js` は robots.txt が閉じた頁を頼みません。
本番の robots.txt がそのコミットのものと同じになるまで待ってから頼みます。`--dry-run` は、頼まずに、頼む頁と頼まない頁を出します。
